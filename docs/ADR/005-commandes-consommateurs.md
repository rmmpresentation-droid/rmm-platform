# ADR 005 — Commandes consommateurs en préproduction

L'administration peut choisir « Networker » ou « Consommateur » dans Commandes. Pour un consommateur, elle sélectionne une fiche prospect existante ou crée une nouvelle fiche (nom et téléphone requis, e-mail facultatif) en même temps que le brouillon ; aucun compte utilisateur n'est créé et le statut de prospection n'est pas changé. Il n'y a pas de détection des doublons : rechercher le client avant de le créer. Les coordonnées sont figées dans le brouillon ; une modification ultérieure de la fiche ne modifie pas les anciennes commandes.

Le consommateur peut acheter un pack avec ses options répétables et son prix issu des règles versionnées de préproduction, ou des produits individuels dont l'administrateur saisit les prix unitaires en DT ; le serveur calcule le total en millimes. La règle S Hydro existante (commande séparée, profil Silver vérifié) reste applicable : S Hydro n'est donc pas proposé dans une commande consommateur sans compte networker et ne peut pas être ajouté à ses options ou produits. Aucun prix public ni paiement en ligne n'est ajouté. Les PP de packs sont conservés dans l'instantané sans attribution automatique au consommateur ; pas de commissions automatiques.

Les commandes réseau existantes restent dans leur table inchangée ; `commerce_consumer_orders` conserve les nouvelles commandes et leur lien à la fiche prospect. Les règles, options, composition, prix et coordonnées sont figés ; le stock par format est déduit à la validation sous verrou transactionnel, avec journal de mouvement. Un prospect lié ne peut pas être supprimé. Les anciennes fiches de commandes restent séparées et ne modifient pas ce stock.

Tests via pg-mem, pas de test de concurrence, rollback ou migration sur PostgreSQL réel ; parcours connecté et responsive à vérifier. La nouvelle table ne figure pas dans la sauvegarde applicative historique : sauvegarde/restauration complète non validée. Pas de données réelles ni production sans GO PROD.
